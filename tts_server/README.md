# Kashmiri TTS server

This is the production adapter between the fine-tuned Bolbosh/Matcha-TTS
checkpoint and the TanStack application. The browser never receives model
weights; the app server calls `POST /api/synthesize` and returns the generated
WAV to the Listen button.

## Start it

```bash
git clone https://github.com/gaash-lab/Bolbosh.git
pip install -r Bolbosh/requirements.txt  # Python 3.10/3.11 recommended
cd Bolbosh
python setup.py build_ext --inplace
pip install -r ../kashmiriBot/tts_server/requirements.txt

export MATCHA_CHECKPOINT=/models/kashmiri-finetuned.ckpt
export HIFIGAN_CHECKPOINT=/models/g_02500000
export MATCHA_SPEAKER=423
export MATCHA_STEPS=8
export MATCHA_TEMPERATURE=0.55
export KASHMIRI_CORPUS_ROWS=/models/kashmiri-tts/rows.jsonl
cd ../kashmiriBot
PYTHONPATH=../Bolbosh:. uvicorn tts_server.app:app --host 0.0.0.0 --port 8000
```

When the repository is not on `PYTHONPATH`, run from the application root and
add the Bolbosh checkout to it:

```bash
PYTHONPATH=/path/to/Bolbosh:/path/to/kashmiriBot uvicorn tts_server.app:app --host 0.0.0.0 --port 8000
```

Set `KASHMIRI_TTS_URL=https://your-tts-host.example` in the deployed app. The
existing `synthesizeKashmiri` server function requests the male Kashmiri voice
by default and passes the selected dialect to this endpoint. The endpoint accepts
`kupwara`, `bandipora`, `shopian`, and `islamabad`; requests for any other
dialect or a non-male voice are rejected for this male checkpoint. This service handles new text with the fine-tuned checkpoint and
returns `source: fine_tuned_dataset`; the app displays that provenance in the
Listen button. The public GAASH-Lab Matcha Space is used only if this service
is unavailable.

For a production checkpoint generated by `scripts/fine_tune_kashmiri.py`, point
`MATCHA_CHECKPOINT` at `artifacts/kashmiri-finetune/best.ckpt`. The service
loads the expanded vocabulary stored in that checkpoint, so the deployed model
and transcript cleaner remain version-matched.

The service is intentionally separate from Cloudflare Workers because PyTorch,
the vocoder, and the checkpoint require a GPU-capable Python runtime.

`KASHMIRI_CORPUS_ROWS` is optional but recommended. Point it at the
`rows.jsonl` produced by `prepare_kashmiri_tts.py --mendeley-dir ...`; the
service then returns the normalized 22.05 kHz male reference WAV for an exact
corpus transcript and uses the fine-tuned model for unseen text. `/healthz`
reports the number of loaded reference pairs so deployment can be verified
without guessing which voice is being used.

## Speed and clarity

Generated files are cached by text, dialect, speaker, checkpoint, diffusion
steps, and temperature, so repeated phrases return immediately from disk.
`MATCHA_STEPS=8` is the default speed/quality balance. Increase it to `10` or
`12` for clearer but slower audio; reduce it to `6` only when latency matters
more than naturalness. `MATCHA_TEMPERATURE=0.55` keeps the male voice steadier
than the public demo default. The runtime removes DC offset, normalizes RMS,
limits peaks, and adds short fades before writing 16-bit WAV output.
